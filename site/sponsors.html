Sponsor SenderFinder

SenderFinder is free, open source and has no paid tier. Sponsorship supports me as the person building and maintaining it. My current goal is about $500 a month in sponsorship income, helping me keep working on the project and save for a Tesla Model Y.

Last checked: 25 October 2026.

Why sponsor it

SenderFinder exists because the tools that used to answer “who is this sender?” kept disappearing. Rapportive was acquired and shut down. Clearbit Connect stopped working on 30 April 2025. The replacement is an AGPL-3.0 extension that runs in your browser, uses your own provider keys, and has no SenderFinder account or server in the lookup path.

The direct running costs are small, but there is ongoing work. The provider adapters have to follow catalog and API changes. The benchmark costs money every time it runs because it calls paid provider APIs. Ten UI languages have to be kept in step with every new string. Recurring sponsorship supports my time on this work and the personal goal described below.

Sponsorship is not a vote on the roadmap. The project's value is that it recommends the cheapest step first and says when it is uncertain; a sponsor cannot buy a different answer.

What sponsors get

Sponsorship is recognition, not advertising inventory. The current offer is deliberately small and concrete:

  • A logo and a link on this page, in the sponsors section, once there are sponsors to list.
  • A logo and a link in the repository's README.md, next to the project description.
  • A one-line description of what you do, if you want one, in both places.
  • The honest association with an open-source tool that does not collect inbox data and publishes its benchmark methodology.

What sponsorship does not buy: placement in the extension's About card (that is not offered and should not be assumed), a provider ranking, a favourable benchmark result, a roadmap commitment, access to user data, or the right to approve copy. The project has no user data to sell and no interest in inventing some.

Current sponsors

There are none yet. This project has no sponsors and no paid tier at the time of writing. The section above describes what will be offered when there are; it is not a disguised list of existing supporters.

If that changes, the names will appear here and in the README, with the date they started. No placeholder logo is shown in the meantime.

Provider relationships, disclosed

SenderFinder depends on three data providers. Two aggregate several sources behind one key; the third is an optional fallback. They are commercial services, and the project's relationship with them should be as legible as the lookup path.

The extension never calls a data source directly. BlitzAPI, QuickEnrich and Village are called through treg; Hunter, Apollo and ContactOut through Monid; Data Legion through Firecrawl. An Apollo API key of your own does nothing here, because the request goes through Monid. That is an architectural fact, not a sponsorship claim.

It does not change the waterfall order, the prices shown in settings, or the benchmark. The table is updated when a relationship changes.

How to sponsor

The GitHub Sponsors page is being set up. Until it is live, the practical route is to open an issue on github.com/astonysh/SenderFinder with the subject “sponsorship” and say what you have in mind — one-time, recurring, or in kind (benchmark provider credits are especially useful). The maintainer will reply with a way to contribute.

You can also write to tony@senderfinder.com. GitHub issues remain the public, durable channel; please do not send keys, addresses or other personal data in either.

If you are a provider and want to donate API credits for benchmark runs, say so in the same issue. Credits are used only for the published benchmark, and the methodology and results stay public.

Where the money goes

I started SenderFinder because I needed it myself. Finding the person behind an email and connecting on LinkedIn felt like a real need worth building for, and I hoped other people would find it useful too.

There is also a personal reason: I want to buy a Tesla Model Y. By the time I decided to go for it, the offer I had been looking at had ended. I was not keen to pay the higher price entirely out of pocket, so I gave myself a challenge: build something useful and let sponsorship help pay for the car.

My target is about $500 a month in sponsorship income. Sponsorship supports me as the person building and maintaining SenderFinder, and helps me put money aside for the Model Y. If this tool is useful to you and you choose to sponsor it, you are helping both the project and the person behind it.

What we will not do

  • Sell or share lookup data. The extension has no server in the lookup path and no inbox database.
  • Put a sponsor's provider first in the waterfall, or hide a cheaper step behind a sponsorship.
  • Publish a benchmark result a sponsor paid to change. Reruns may change the numbers; the method does not.
  • Add tracking to this website. The site loads no analytics script and no third-party requests.
  • Promise a feature that is not in the repository. The code is the roadmap.

Questions about sponsorship

The short version before you open an issue.

Is SenderFinder free?

Yes. The extension is AGPL-3.0 open source with no account and no subscription. You pay the data provider directly, with your own key, only for the lookups you run. There is no paid tier to upgrade to.

Who are the current sponsors?

None. At the time of writing the project has no sponsors and no paid tier. This page will list them with a start date when that changes.

Does sponsoring change which provider is recommended?

No. The waterfall order is cheapest-first and the benchmark table is generated from the results file. A sponsor cannot buy a ranking, a favourable result or a place in the extension's About card.

How do I sponsor before GitHub Sponsors is live?

Open an issue on GitHub with the subject “sponsorship” or email tony@senderfinder.com, and describe what you have in mind. Provider credits for benchmark runs are also useful. Do not include keys, addresses or personal data in either.

Use the product first

Sponsorship should follow from the tool being useful, not the other way round. Install it, run a few lookups, and decide after that.
