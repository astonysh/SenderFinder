Email signature parser

Extract LinkedIn, X, website, email and phone details from a pasted signature. Parsing happens in this tab, with no mailbox connection, account or server upload.

Published 29 October 2026. Designed for one plain-text or HTML signature at a time.

Parse an email signature

Paste only the signature block or its HTML source. The parser looks for explicit contact details and labels any inferred name, title or company as best-effort rather than verified.

Do not paste a confidential message thread. Images are not read, and a displayed icon with no URL in the copied text cannot be recovered.

Extracted details

Input and results remain in browser memory until you clear or leave the page. SenderFinder receives neither the signature nor the extracted fields.

What the email signature parser extracts

The reliable fields are details written explicitly in the signature: email addresses, phone-like numbers and web URLs. URLs are grouped into LinkedIn profiles, X or Twitter links and other websites. Duplicate links are removed, common trailing punctuation is cleaned and raw HTML links are read from their href values when present.

The first few non-contact lines are also shown as possible identity lines. A conventional signature often starts with a name, followed by a job title and company, but plain text does not carry a universal label for those fields. Treat those lines as candidates to review, not a verified contact record.

What a local parser cannot recover

  • A LinkedIn icon copied as an image without its underlying URL.
  • Text embedded inside a logo, screenshot or scanned signature.
  • A link hidden behind a redirect when the copied content contains only the visible label.
  • A reliable person identity from a shared address such as sales@ or support@.
  • A guaranteed distinction between a job title, department and company in every language or layout.

Why the parser runs in your browser

Email signatures can contain direct phone numbers, addresses and internal titles. Sending that block to a generic parser creates another copy of data that may not need to exist. This tool uses deterministic browser code and makes no network request, so it is useful for a quick, inspectable extraction.

Local processing does not make careless copying harmless. Paste only the minimum signature block, avoid confidential message content and clear the form on a shared computer. The result is not identity verification and should not be used for screening or high-stakes decisions.

From a signature link to the right LinkedIn profile

When a signature contains a linkedin.com/in URL, that explicit link is usually a better first answer than a paid enrichment call. SenderFinder therefore scans the current message locally before it tries a provider. If the signature has no link, use the LinkedIn profile search builder with the sender's work email, name and company.

Email signature parser questions

Supported input, privacy and the difference between extraction and verification.

Does the email signature parser upload what I paste?

No. The parser runs in the browser and makes no network request. Input remains in the current tab until you clear it or leave the page.

Can it extract a LinkedIn link hidden behind an icon?

Only when the pasted HTML includes the link URL or the copied text exposes it. A bitmap icon by itself contains no destination for the parser to recover.

Can I upload EML or MSG files?

No. This first version accepts pasted plain text or HTML for one signature. It does not connect to a mailbox or parse full EML and MSG containers.

Are the inferred name, title and company verified?

No. They are candidate lines based on position in a conventional signature. Review them against the actual email header and profile before using them.

Scan signatures while you read the email

SenderFinder runs the LinkedIn signature scan locally inside Gmail or Outlook, before any optional paid provider step.
